# MathModelingCode Q3 V1–V4 行为数据分析报告

## 1. 测试口径

在 `D:\\George\\SX\\MathModelingCode` 中使用仓库统一脚本，对 V1、V2、V3、V4 进行同口径离线 P3 评测。

- 每个版本：random、min_reff、collinear 三类场景；每类 10 局；
- random 使用 smooth 误差场；压力场使用 adversarial 误差场；
- n=8、n=9 两组环形搜索配置；
- 成功判据：全部干扰源清除；
- 结果目录：`results/codex_v1-v4_eval_20260912/`。

本报告中的“单位清除点时间”使用每类场景的 `mean_avg_time_per_source_s`，不同场景之间采用简单平均，主要用于版本行为趋势分析。

## 2. 总体结果（n=8）

| 版本 | 全清率 | 三类场景平均总时间 | 平均每点时间 | 平均移动时间 | 平均测量次数 |
|---|---:|---:|---:|---:|---:|
| V1 | 100% | 6353.7 s | 490.6 s/点 | 5586.8 s | 118.4 |
| V2 | 100% | 5129.9 s | 397.2 s/点 | 4359.4 s | 118.4 |
| V3 | 100% | 5140.1 s | 397.4 s/点 | 4369.5 s | 118.7 |
| V4 | 100% | 3505.9 s | 271.9 s/点 | 2917.9 s | 115.8 |

V1–V4 在本批次中均未发生清除失败，因此性能比较可以直接观察单位清除点时间和行为分解。

## 3. 各版本行为变化

### V1：基础策略，主要问题是移动过多

V1 的 n=8 平均移动距离约 30.6–31.0 km，移动时间约 6100–6200 s，远高于后续版本。测量次数与 V2–V3 接近，说明 V1 的主要问题不是测量过多，而是已经获得信息后没有形成高效的全局任务路线。

行为特征：

- 能稳定完成覆盖、定位和清除；
- 找到源后仍然产生较多跨区域移动；
- 条件路由 Oracle gap 接近 95%–110%，说明实际路线远离可用路线基准；
- 单位清除点时间约 397–540 s，随机场最差。

### V2：联合任务路线规划带来第一轮明显收益

V2 将平均总时间从 V1 的 6353.7 s 降至 5129.9 s，下降约 19.3%；平均每点时间从 490.6 s 降至 397.2 s，下降约 19.0%。

最明显变化来自移动：平均移动时间从约 5587 s 降至 4359 s，减少约 1227 s。测量次数基本没有下降，说明 V2 的收益主要来自“目标排序和任务路线”，不是减少感知动作。

行为特征：

- 开始把多个已发现目标作为联合任务处理；
- 减少了局部发现后立即往返的行为；
- 路线效率显著提高；
- 仍然保留较多固定或阶段性路径成本。

### V3：动态清除插入，平均收益有限但行为更稳定

V3 与 V2 的总体均值非常接近：n=8 平均总时间约 5140.1 s，平均每点约 397.4 s/点。相较 V2，V3 并没有在本次三类场景平均上形成明显净加速。

但这不代表 V3 没有作用。V3 的动态清除插入主要改善的是任务执行顺序和在线决策，而不是大幅减少总移动。在 random 场景中，V3 比 V2 略快；在 min_reff 场景中，V3 略慢；在 collinear 场景中二者接近。

行为特征：

- 可以把新发现的清除任务动态插入当前路线；
- 对不同几何布局的收益不稳定；
- 在信息质量较差或目标顺序复杂时，动态重排带来的计算/路线变化可能抵消收益；
- 仍未解决 V2 遗留的较高移动成本。

### V4：滚动动态路由，形成主要性能跃迁

V4 n=8 平均总时间约 3505.9 s，相比 V3 的约 5473.4 s 下降约 35.9%；平均每点时间约 271.9 s，较 V3 下降约 31.6%。

V4 的核心收益再次来自移动：

- V3 平均移动时间约 4369.5 s；
- V4 平均移动时间约 2917.9 s；
- 减少约 1452 s，降幅约 33.2%。

测量次数只从约 118.7 次降至 115.8 次，切频次数也变化不大，因此 V4 的主要行为变化不是“少测很多”，而是“使用当前信息重新组织下一段路线”。

行为特征：

- 每获得新信息后重新评估剩余任务；
- 更早地把定位任务、清除任务和路线合并；
- 减少已经知道目标之间的重复折返；
- 在 random、min_reff、collinear 三类场景都保持收益；
- conditional route oracle gap 降到约 7.6%–10.3%，明显优于 V1–V3。

## 4. 场景鲁棒性

### Random

n=8 平均总时间：

- V1：6991.3 s；
- V2：5768.8 s；
- V3：5689.0 s；
- V4：3877.9 s。

V4 比 V1 快约 44.5%，比 V3 快约 31.8%。随机场最能体现全局路线和滚动规划的收益。

### min_reff

n=8 平均总时间：

- V1：6928.1 s；
- V2：6114.0 s；
- V3：6210.7 s；
- V4：3803.3 s。

V4 比 V3 快约 38.8%。最低有效接收半径会增加搜索和定位压力，但没有降低任何版本的全清率。

### Collinear

n=8 平均总时间：

- V1：5141.7 s；
- V2：3507.0 s；
- V3：3520.6 s；
- V4：2836.7 s。

共线场景中 V2 已有较大收益，V4 仍进一步降低约 19.4%。这说明 V4 的优势不只来自处理随机分布，也能在结构化几何场景中继续压缩路线。

## 5. 关键结论

1. V1–V4 在本批次均达到 100% 全清，版本演进没有以牺牲正确性换取速度。
2. V1 的主要缺陷是移动路线效率低，而不是测量次数过多。
3. V2 是第一次明显的全局行为改进，联合任务路线规划使单位清除点时间下降约 19%。
4. V3 的动态清除插入改善了在线任务组织，但平均性能相对 V2 基本持平，收益依赖场景。
5. V4 的主要贡献是滚动动态路由，而不是大幅减少测量；它把最大瓶颈从“路线组织”进一步压缩。
6. V4 的单位清除点时间约 272 s/点，较 V1 的约 491 s/点下降约 44.6%。
7. 当前剩余瓶颈仍是移动，但 V4 的 conditional route gap 已明显缩小；后续更可能需要减少搜索任务生成、定位补测和信息获取成本，而不是只继续优化 TSP 顺序。

## 6. 证据边界

本报告使用的是仓库自带的本地离线模拟器和固定种子，不是官方正式测试。所有版本均只实现/评测问题 3；不能据此推断问题 4 性能。仓库全量 pytest 仍有 6 个 HTTP 测试因缺少 `client` fixture 无法执行，但本次 V1–V4 离线评测均正常完成，时间分解误差在微秒级。
